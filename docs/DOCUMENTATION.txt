================================================================================
  1. VUE D'ENSEMBLE
================================================================================

  Ce projet scrape automatiquement les données d'athlètes depuis le site
  athle.fr (Fédération Française d'Athlétisme) et les stocke dans une base
  de données MySQL normalisée.

  Le système :
  - Lit une liste d'URLs d'athlètes depuis une BDD distante (Hostinger)
  - Pour chaque athlète, scrape 3 pages d'athle.fr
  - Extrait 9 catégories de données (identité, clubs, médailles, etc.)
  - Insère tout dans une BDD locale normalisée (16 tables, 30 FK)
  - Passe automatiquement à l'athlète suivant toutes les 1 seconde

  Technologies : PHP 7+, MySQL/MariaDB, HTML parsing par regex

  ─────────────────────────────────────────
  4.1  index.php — ORCHESTRATEUR
  ─────────────────────────────────────────

  Rôle : Point d'entrée unique. Coordonne les 7 étapes du pipeline.

  Contient un bouton HTML de réinitialisation (lien vers reset.php)
  affiché en haut de page sous forme d'icône de rechargement.

  Appelle :
    → url.php           (via require_once) — fournit l'URL
    → json_athle.php    (via require_once) — exporte en JSON + sauvegarde fichier
    → dbCheck_athle.php (via require_once) — crée les tables
    → insert_athle.php  (via require_once) — insère les données

  Utilise :
    → DatabaseHandler   (classe) — connexion MySQL
    → AthleteScraper    (classe) — scraping athle.fr

  Variables transmises aux fichiers appelés :
    → url.php reçoit :           $dbname, $username, $password (Hostinger)
    → json_athle.php reçoit :    $scraper (données extraites)
    → dbCheck_athle.php reçoit : $databaseHandler (connexion locale)
    → insert_athle.php reçoit :  $scraper + $databaseHandler

  Techniques :
    → ob_start() pour permettre header() après des echo
    → $_SESSION["url"] comme compteur persistant
    → header("Refresh: 1") pour la boucle automatique

  Bouton reset :
    → Lien HTML <a href="reset.php"> avec icône de rechargement
    → Placé entre le bloc PHP d'initialisation et le bloc PHP principal
    → Permet de réinitialiser le compteur à 0 en un clic


  ─────────────────────────────────────────
  4.2  url.php — DISTRIBUTEUR D'URLs
  ─────────────────────────────────────────

  Rôle : Gère le compteur de session et récupère l'URL de l'athlète courant.

  Entrées (depuis index.php) :
    → $dbname, $username, $password : credentials BDD distante
    → DatabaseHandler : classe déjà chargée

  Sorties (variables disponibles après require) :
    → $id_nom_et_liens        : numéro de l'athlète en cours (0, 1, 2...)
    → $mes_projets[0]["url"]  : URL athle.fr de l'athlète

  Fonctionnement :
    1. Si $_SESSION["url"] n'existe pas → l'initialise à 0
    2. $id_nom_et_liens = $_SESSION["url"]
    3. Connexion BDD distante
    4. SELECT * FROM nom_et_liens WHERE id_nom_et_liens = $id_nom_et_liens
    5. Résultat dans $mes_projets (variable globale)

  Table distante utilisée :
    nom_et_liens
    ├── id_nom_et_liens  (INT, PK, auto-increment)
    └── url              (VARCHAR, URL athle.fr)


  ─────────────────────────────────────────
  4.3  dbCheck_athle.php — CRÉATION SCHEMA BDD
  ─────────────────────────────────────────

  Rôle : Crée les 16 tables + 30 FK si elles n'existent pas.

  Entrée (depuis index.php) :
    → $databaseHandler : instance DatabaseHandler connectée à la BDD locale

  Fonctionnement :
    1. $tables = getAllTables() — liste les tables existantes
    2. Pour chaque table :
       if (!in_array($tableName, $tables)) → create_table()
    3. Pour chaque FK :
       addForeignKey() — ignore si elle existe déjà
    4. Pour les tables existantes :
       SHOW COLUMNS → ALTER TABLE ADD COLUMN si colonnes manquantes

  Tables créées : voir section 5 de ce document


  ─────────────────────────────────────────
  4.4  insert_athle.php — INSERTION DONNÉES
  ─────────────────────────────────────────

  Rôle : Insère toutes les données scrapées dans la BDD normalisée.

  Entrées (depuis index.php) :
    → $scraper         : instance AthleteScraper avec toutes les données
    → $databaseHandler : instance DatabaseHandler connectée

  Helpers définis dans ce fichier :
    → fk($val)                    : retourne "NULL" ou "'valeur'" pour SQL
    → getCategorieId($db, $code)  : cherche id_categorie par code FFA
    → getOrInsertId($db, ...)     : insert-or-get-ID sur table de référence

  9 sections d'insertion :
    1. Identité athlète    → athletes (INSERT ou UPDATE)
    2. Clubs               → athlete_clubs
    3. Médailles           → athlete_medailles
    4. Sélections          → athlete_selections
    5. Progressions        → athlete_progressions
    6. Records             → athlete_records
    7. Podiums             → athlete_podiums
    8. Résultats           → athlete_resultats
    9. Niveaux             → athlete_niveaux + athlete_niv_perfs


  ─────────────────────────────────────────
  4.5  setup_bdd.php — CRÉATION BDD AUTONOME
  ─────────────────────────────────────────

  Rôle : Fichier autonome pour créer la BDD + tables sur n'importe quel serveur.

  Usage : Modifier $dbname/$username/$password en haut du fichier, puis lancer.

  Fonctionnement :
    1. Connexion MySQL brute (sans BDD)
    2. CREATE DATABASE IF NOT EXISTS $dbname
    3. Connexion via DatabaseHandler
    4. require dbCheck_athle.php → crée toutes les tables
    5. Ferme la connexion

  Ne dépend PAS de index.php — peut être lancé seul.


  ─────────────────────────────────────────
  4.6  AthleteScraper.php — CLASSE SCRAPER
  ─────────────────────────────────────────

  Rôle : Télécharge et parse les pages athle.fr d'un athlète.

  Constructeur :
    new AthleteScraper($input)
    → $input peut être un ID (809035) ou une URL complète

  Méthode principale :
    scrapeAll() → télécharge 3 pages, appelle toutes les méthodes d'extraction

  Méthodes d'extraction (9) :
    extractIdentite()     → nom, naissance, taille, poids, catégorie, nationalité
    extractClubs()        → déduit les clubs depuis les progressions
    extractMedailles()    → or/argent/bronze + compétition + épreuve
    extractSelections()   → sélections nationales + performances
    extractProgressions() → meilleures perfs par saison et épreuve
    extractRecords()      → records personnels par épreuve
    extractPodiums()      → titres de champion (3 niveaux)
    extractResultats()    → résultats par compétition (année courante)
    extractNiveaux()      → classement annuel + perfs qualificatives

  Méthodes utilitaires :
    splitNomPrenom()      → sépare "VAN DER ZYPPE Antonine" en nom/prénoms
    getCategorieCode()    → calcule la catégorie FFA depuis l'âge
    performanceToInt()    → convertit "6''37" en 637 (centièmes)
    convertDateToSql()    → convertit "25 Juil 1997" en "1997-07-25"

  Propriétés publiques (données extraites) :
    $scraper->identite     → array
    $scraper->clubs        → array
    $scraper->medailles    → array
    $scraper->selections   → array
    $scraper->progressions → array
    $scraper->records      → array
    $scraper->podiums      → array
    $scraper->resultats    → array
    $scraper->niveaux      → array

  Pattern d'extraction commun :
    1. Isoler la section HTML (data-section="..." → </section>)
    2. preg_match_all('/<tr([^>]*)>(.*?)<\/tr>/si', ...)
    3. Ignorer les <tr> avec "detail-row" (lignes mobiles)
    4. Ignorer les <tr> avec <th> (en-têtes)
    5. Extraire les <td>, strip_tags, nettoyer
    6. Valider (année = 4 chiffres, perf contient chiffre, etc.)


  ─────────────────────────────────────────
  4.7  DatabaseHandler.php — CLASSE CRUD
  ─────────────────────────────────────────

  Rôle : Gestion complète d'une BDD MySQL.

  Méthodes clés utilisées dans ce projet :
    → new DatabaseHandler($db, $user, $pass) : connexion
    → closeConnection()                       : fermeture
    → getAllTables()                           : liste des tables
    → create_table($name, $columns)           : création table
    → addForeignKey($t, $col, $ref, $refCol)  : création FK
    → action_sql($sql)                        : exécution SQL générique
    → select_custom_safe($sql, $global)       : SELECT + variable globale
    → $connection->query($sql)                : requête directe
    → $connection->insert_id                  : dernier ID inséré
    → $connection->real_escape_string($val)   : échappement SQL

  ─────────────────────────────────────────
  4.9  json_athle.php — EXPORT JSON
  ─────────────────────────────────────────

  Rôle : Exporte les données scrapées en JSON et les sauvegarde dans un fichier.

  Entrée (depuis index.php) :
    → $scraper : instance AthleteScraper avec données extraites

  Fonctionnement :
    1. Récupère l'ID athlète depuis $scraper->identite['athlete_id']
    2. Crée le dossier src/ à la racine du projet si inexistant
    3. Génère un fichier PHP qui :
       - Envoie les headers CORS (Access-Control-Allow-Origin: *)
       - Envoie le Content-Type application/json
       - Affiche le JSON brut après la fermeture du bloc PHP
    4. Sauvegarde dans src/{athlete_id}.php (écrase si existe déjà)
    5. Affiche "JSON créé" ou "JSON écrasé" selon que le fichier existait déjà

  Sortie :
    → Fichier src/{athlete_id}.php (fichier PHP autonome avec headers CORS + JSON)
    → Exemples : src/809035.php, src/1384398.php, etc.

  Anti-doublon :
    → file_put_contents() écrase automatiquement le fichier existant
    → Même logique que l'anti-doublon BDD : données toujours à jour

  Accès externe :
    → Les fichiers JSON sont accessibles via URL directe
    → Ex: http://localhost/BK/src/809035.php
    → Le header CORS autorise l'accès cross-origin (AJAX, fetch, etc.)


  ─────────────────────────────────────────
  4.10  reset.php — RÉINITIALISATION
  ─────────────────────────────────────────

  Rôle : Remet le compteur de scraping à 0 et relance le processus.

  Fonctionnement :
    1. session_start()   → reprend la session active
    2. session_destroy() → détruit toute la session (dont $_SESSION["url"])
    3. header("Location: index.php") → redirige vers index.php
    4. exit → arrête l'exécution

  Résultat :
    → index.php redémarre avec $_SESSION["url"] inexistant
    → url.php initialise le compteur à 0
    → Le scraping recommence depuis le premier athlète

  Accès :
    → Directement via URL : http://localhost/BK/reset.php
    → Via le bouton de réinitialisation dans index.php (icône en haut de page)

================================================================================
  7. HELPERS ET UTILITAIRES
================================================================================

  fk($val)
    Entrée : n'importe quelle valeur
    Sortie : "NULL" si null/0, "'valeur'" sinon
    Usage  : construire des requêtes SQL avec FK nullable

  getOrInsertId($db, $table, $colId, $colNom, $valeur, $extraCols)
    Entrée : table de référence + valeur à chercher
    Sortie : ID existant ou ID du nouvel enregistrement
    Logique :
      1. SELECT id FROM table WHERE nom = 'valeur' LIMIT 1
      2. Si trouvé → retourne l'ID
      3. Sinon → INSERT INTO table (nom) VALUES ('valeur') → retourne insert_id
    Usage  : éviter les doublons dans villes, clubs, epreuves, etc.

  getCategorieId($db, $code)
    Entrée : code catégorie FFA ("SE", "JU", "ES"...)
    Sortie : id_categorie correspondant dans la table categories
    Usage  : transformer un code texte en FK entière



================================================================================
  8. SYSTÈME ANTI-DOUBLON
================================================================================

  Problème : si on relance le scraping d'un athlète déjà en BDD,
             on ne veut pas de doublons.

  Solution (dans insert_athle.php) :

  ┌─────────────────────────────────────────────────────────────────┐
  │ 1. SELECT id_athlete FROM athletes                              │
  │    WHERE athlete_id_externe = {id_athle.fr}                     │
  │                                                                 │
  │ 2a. SI L'ATHLÈTE EXISTE :                                      │
  │     → UPDATE athletes SET nom=..., naissance=... (màj infos)    │
  │     → DELETE FROM athlete_clubs WHERE id_athlete = X            │
  │     → DELETE FROM athlete_medailles WHERE id_athlete = X        │
  │     → DELETE FROM athlete_selections WHERE id_athlete = X       │
  │     → DELETE FROM athlete_progressions WHERE id_athlete = X     │
  │     → DELETE FROM athlete_records WHERE id_athlete = X          │
  │     → DELETE FROM athlete_podiums WHERE id_athlete = X          │
  │     → DELETE FROM athlete_resultats WHERE id_athlete = X        │
  │     → DELETE FROM athlete_niveaux WHERE id_athlete = X          │
  │       (athlete_niv_perfs se vide automatiquement par CASCADE)   │
  │     → RE-INSERT toutes les données fraîches                     │
  │                                                                 │
  │ 2b. SI L'ATHLÈTE EST NOUVEAU :                                 │
  │     → INSERT INTO athletes (...) → récupérer id_athlete         │
  │     → INSERT toutes les données enfants                         │
  └─────────────────────────────────────────────────────────────────┘

  Avantages :
  - id_athlete reste stable (pas de changement d'ID)
  - Les données sont toujours à jour
  - Les tables de référence (villes, clubs...) ne sont jamais supprimées
    → getOrInsertId() évite les doublons naturellement



================================================================================
  9. BOUCLE AUTOMATIQUE (session + refresh)
================================================================================

  Le système traite les athlètes un par un automatiquement :

  Cycle 1 : $_SESSION["url"] = 0
    → url.php : SELECT WHERE id = 0 → URL athlète A
    → scrape A → insère A
    → $_SESSION["url"]++ → vaut 1
    → header("Refresh: 1") → recharge dans 1s

  Cycle 2 : $_SESSION["url"] = 1
    → url.php : SELECT WHERE id = 1 → URL athlète B
    → scrape B → insère B
    → $_SESSION["url"]++ → vaut 2
    → header("Refresh: 1") → recharge dans 1s

  Cycle 3 : $_SESSION["url"] = 2
    → ...

  La boucle continue jusqu'à ce qu'il n'y ait plus d'URL dans nom_et_liens.

  Pour réinitialiser le compteur :
    → Cliquer sur le bouton de reset en haut de la page index.php
    → Ou ouvrir directement reset.php dans le navigateur
    → reset.php détruit la session et redirige vers index.php
    → Le scraping recommence depuis l'athlète 0

  Note technique :
    ob_start() est obligatoire car header() ne fonctionne que si
    AUCUN output HTML n'a été envoyé au navigateur. ob_start() met
    tout en buffer, et le buffer est envoyé à la fin du script.



================================================================================
  10. CONVERSION DES PERFORMANCES
================================================================================

  La méthode performanceToInt() convertit les notations athle.fr
  en entier standardisé (centièmes de seconde ou centimètres) :

  TEMPS :
    "6''37"        → 637        (6 sec 37 centièmes)
    "3'43''65"     → 22365      (3 min 43 sec 65 centièmes)
    "12'09"        → 72900      (12 min 09 sec)
    "1h23'45''12"  → 503512     (1h 23min 45sec 12 centièmes)

  DISTANCES :
    "7.34"         → 734        (7 mètres 34 centimètres)
    "6m30"         → 630        (6 mètres 30 centimètres)
    "15.67"        → 1567       (15 mètres 67 centimètres)

  VENT :
    Extrait séparément : "10''45 (-0.1)" → perf="10''45", vent="-0.1"

  DATES (convertDateToSql) :
    "25/07/1997"     → "1997-07-25"
    "25 Juil 1997"   → "1997-07-25"
    "26 Avr. 2025"   → "2025-04-26"
    Supporte tous les mois en français (janv, févr, mars, avr, mai,
    juin, juil, août, sept, oct, nov, déc + variantes)



================================================================================
  11. PROBLÈMES RÉSOLUS
================================================================================

  A) MÉLANGE ÉPREUVES / PERFORMANCES
     Symptôme : des noms d'épreuves apparaissaient comme performances
     Cause    : preg_replace pour nettoyer detail-row échouait sur du
                HTML volumineux (limite backtracking PCRE)
     Fix      : vérifier "detail-row" dans les attributs <tr> au lieu
                de supprimer les lignes par regex

  B) DONNÉES PODIUMS POLLUANT LES PROGRESSIONS
     Symptôme : "5m59 (NC)" apparaissait comme nom de club
     Cause    : la section Podiums (section_6) n'était pas bornée,
                ses colonnes (Année|Place|Épreuve|Perf|Date|Lieu) étaient
                parsées comme des Progressions (Saison|Date|Perf|Club|Lig|Lieu)
     Fix      : ajout de la borne </section> pour isoler chaque section

  C) FK TROP LONGUE (67 > 64 CHARS)
     Symptôme : MySQL erreur "Identifier name too long"
     Cause    : fk_athlete_niveau_performances_id_niveau_athlete_niveaux_id_niveau
     Fix      : renommé la table en athlete_niv_perfs

  D) HEADER() APRÈS ECHO
     Symptôme : "headers already sent" quand header("Refresh: 1")
     Cause    : des echo envoyaient du HTML avant le header()
     Fix      : ob_start() en début de script

  ───────────────────────

  Ouvrir index.php dans le navigateur.
  La page se rafraîchit toute seule toutes les 1 seconde.
  Chaque refresh traite 1 athlète.

  ───────────────────────────

  Option A : Cliquer sur le bouton de reset (icône) en haut de la page index.php
  Option B : Ouvrir directement http://localhost/BK/reset.php
  → Dans les deux cas, la session est détruite et le scraping repart de 0.

  ACCÉDER AUX DONNÉES JSON :
  ──────────────────────────

  Chaque athlète scrapé a son fichier JSON dans src/ :
    → http://localhost/BK/src/809035.php
    → http://localhost/BK/src/1384398.php

  Les fichiers sont accessibles en cross-origin grâce au header CORS.
  Exemple d'accès en JavaScript :
    fetch("http://localhost/BK/src/809035.php")
      .then(r => r.json())
      .then(data => console.log(data));

  ───────────────────────

  Insérer de nouvelles lignes dans la table nom_et_liens
  sur la BDD distante avec les URLs athle.fr.

  pour tester le parsing sans faire de requêtes réseau.

  - index.php (section "Connexion BDD locale")
