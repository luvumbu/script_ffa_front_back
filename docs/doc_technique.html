📚 Presentation

Bokonzi est une plateforme complete de donnees d'athletisme francais. Elle collecte les donnees de athle.fr pour 300 000+ athletes, les stocke en base de donnees MySQL, et les expose via une API REST et un dashboard interactif avec graphiques, comparaisons, fiches detaillees, biographies auto-generees, QR codes dynamiques et SEO avance.

🚀 API REST

21 endpoints JSON. Tous retournent {"success": true/false, ...}. CORS active (Allow-Origin: *). Cache fichier JSON avec TTL 24h sur les endpoints lourds.

Base URL : https://bokonzi.com/api/ (prod) ou /BK/api/ (local)

Authentification (4 endpoints)

POST /api/auth/login.php
Connexion — retourne un token + cookie HttpOnly (30 jours)
Params (JSON body) : email, password
Response : { success, token, user: { id_user, email, nom, prenom, role, id_athlete } }
POST /api/auth/register.php
Inscription — cree le compte + auto-login
Params : email, password (8+ chars), nom, prenom, role (athlete|coach|club)
Response : 201 Created { success, token, user }
POST /api/auth/logout.php
Deconnexion — supprime la session en BDD + efface le cookie
GET /api/auth/me.php
Utilisateur courant — verifie le cookie de session
Response : { success, authenticated: true/false, user }

Athletes & Recherche (3 endpoints)

GET /api/athlete.php
Profil complet d'un athlete — 10 categories : identite, clubs, medailles, records, progressions, resultats, podiums, selections, niveaux + sous-performances
Params : ?id= (athlete_id_externe athle.fr) ou ?id_athlete= (ID interne BDD)
Cache : 24h fichier JSON
GET /api/search.php
Recherche avancee multi-criteres (12 filtres combinables)
Filtres : ?nom= ?nom1= ?nom2= ?club= ?categorie= ?sexe= ?nationalite= ?epreuve= ?ville= ?competition= ?medaille= ?annee= ?licence=
Pagination : ?page= ?limit= (max 100)
Retourne aussi : niveaux[] et top_records[] (top 5) par athlete
GET /api/liste.php
Liste paginee de tous les athletes avec tri
Tri : ?ordre= nom | date | id | recent | medailles | podiums | selections | records
Pagination : ?page= ?limit= (max 100, defaut 50)

Statistiques & Classements (4 endpoints)

GET /api/stats.php
Statistiques globales — totaux + top performers + distributions. Cache 24h (10min pour detail).
Params : ?detail=1 (ajoute tops clubs/epreuves/villes, repartitions), ?top=N (defaut 50, max 200), ?nocache=1 (force recalcul)
GET /api/classement.php
Classement des athletes par epreuve — tries par meilleure performance
Params : ?epreuve=ID (requis), ?categorie= ?sexe= ?annee= ?limit= ?offset=
GET /api/club_stats.php
Statistiques detaillees d'un club — athletes, repartitions, epreuves paginees, medailles, podiums, top athletes, evolution
Params : ?id= ou ?nom= (requis), ?ep= (page epreuves)
GET /api/ville_stats.php
Statistiques detaillees d'une ville — athletes, repartitions, epreuves, clubs, medailles, podiums, records pagines, selections, progressions, evolution 15 ans
Params : ?nom= (requis)

Donnees de reference (6 endpoints)

GET /api/epreuve_stats.php
Statistiques detaillees d'une epreuve — records pagines classes, repartitions, medailles, podiums, top clubs/villes, niveaux, evolution. Cache 24h.
Params : ?nom= (requis), ?page= ?limit= (max 100), ?sexe= ?categorie=
GET /api/epreuve_records.php
Top 50 records pour une epreuve — avec athlete, categorie, sexe, nationalite, club, niveaux
Params : ?nom= (requis)
GET /api/clubs.php /api/epreuves.php /api/villes.php /api/competitions.php
Listes paginables avec recherche par nom et comptage d'athletes. Clubs retournent aussi top_niveaux (top 3).

GET POST PUT DELETE /api/performances.php

🔌 Pipeline de scraping

Flux de donnees

1. SOURCE athle.fr/athletes/{id}/bilans athle.fr/athletes/{id}/records athle.fr/athletes/{id}/selections | v curl_multi (7 athletes x 3 pages = 21 requetes paralleles) 2. TELECHARGEMENT scraping/scrape_functions.php → scrapeParallel() Retourne : [athleteId → [bilans → html, records → html, selections → html]] | v AthleteScraper (parsing HTML) 3. EXTRACTION Class/AthleteScraper.php 9 sections extraites : identite, clubs, medailles, selections, progressions, records, podiums, resultats, niveaux | v Sauvegarde double 4. STOCKAGE JSON → src/{athleteId}.php (fichier statique avec headers PHP) BDD → insertAthleteData() via core/insert_athle.php Cache memoire des tables de reference (0 SELECT pour villes/clubs/epreuves connus) | v 5. API + SEO Les endpoints API lisent la BDD + cache fichier JSON (24h TTL) Le module core/seo.php lit directement les fichiers src/ pour le SEO (~1ms) Les pages frontend appellent l'API pour afficher les donnees

Flux d'authentification

INSCRIPTION register.php → POST /api/auth/register.php → Validation (email unique, password 8+ chars, role) → password_hash(bcrypt) → INSERT users → createSession() → INSERT user_sessions (token 64 hex chars, expire +30j) → Set cookie bk_token (HttpOnly, SameSite=Lax, 30 jours) → Redirect index.php CONNEXION login.php → POST /api/auth/login.php → SELECT user by email → password_verify(bcrypt) → createSession() → token + cookie → Redirect index.php VERIFICATION (chaque page) Cookie bk_token → getCurrentUser($conn) → SELECT user_sessions WHERE token = ? AND expire_at > NOW() → JOIN users → retourne {id_user, email, nom, prenom, role, id_athlete} DECONNEXION POST /api/auth/logout.php → DELETE FROM user_sessions WHERE token = ? → Clear cookie (expires = past)

sitemap.php — Sitemap XML dynamique

Google utilise les sitemaps pour decouvrir et indexer les pages d'un site. Bokonzi genere un sitemap XML dynamique depuis la base de donnees.

STRUCTURE DU SITEMAP sitemap.php → Sitemap Index (liste tous les sous-sitemaps) sitemap.php?page=0 → Pages principales (accueil, recherche, athletes, classement) sitemap.php?page=1 → Athletes 1 → 500 sitemap.php?page=2 → Athletes 501 → 1000 ... sitemap.php?page=660 → Athletes 329501 → 330000 Total : 660+ sous-sitemaps x 500 athletes = 330 000+ URLs indexees
Pourquoi 500 par page ? Google limite a 50 000 URLs / 50 Mo par sitemap. Hostinger coupe la sortie PHP au-dela d'une certaine taille. 500 athletes par sous-sitemap garantit que chaque fichier XML reste petit et complet.

📲 QR Codes dynamiques

Un QR code est un code-barres 2D que l'on peut scanner avec un telephone pour ouvrir directement une page web. Bokonzi genere des QR codes pour chaque element affiche, sans rien stocker sur le serveur.

Comment ca marche ? Les QR codes sont generes a la volee par le service externe api.qrserver.com. Une simple balise <img> avec l'URL de la page en parametre suffit. L'image est creee par le serveur distant et affichee directement dans la page.

// Fonction JavaScript globale pour generer un QR code
function bkQR(url) {
    return '<div class="qr-share">' +
        '<img src="https://api.qrserver.com/v1/create-qr-code/?size=120x120&data=' +
        encodeURIComponent(url) +
        '" alt="QR Code" width="120" height="120">' +
        '<div class="qr-label">Scannez pour partager</div></div>';
}

Comparaison multi-athletes (progression, radar, medailles, resume textuel avec verdict) et multi-clubs (effectifs, categories, medailles, specialisation).
