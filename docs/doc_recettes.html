Recettes de code — les patterns récurrents

Les 10 motifs qu'on retrouve partout. Les reconnaître = lire le code beaucoup plus vite.
Le projet n'a pas de framework, mais il a des conventions maison répétées dans presque tous les fichiers. Voici les 10 plus importantes, avec un extrait réel et l'endroit où la trouver. Quand tu reprends un fichier, tu reconnaîtras ces motifs immédiatement.
1 · Cache fichier (MD5 + TTL) 2 · Pagination 3 · Batch query (anti N+1) 4 · Filtre universel $athFilter 5 · Temps vs distance 6 · Chart.js 7 · IP réelle (CloudFlare) 8 · Protection des fichiers de logs 9 · Hiérarchie des niveaux 10 · Barème FFA (perf → niveau)

1 · Cache fichier (MD5 + TTL 24 h)

Ex. : api/club_stats.php:36-45 — présent dans presque tous les endpoints.

$cacheKey  = 'clubstats_' . md5($idClub.'_'.$nomClub.'_'.$annee. … );
$cacheFile = $cacheDir . '/' . $cacheKey . '.json';
if (!$noCache && file_exists($cacheFile) && (time() - filemtime($cacheFile)) < 86400) {
    echo file_get_contents($cacheFile); $conn->close(); exit;   // CACHE HIT
}
// … sinon on calcule, puis :
@file_put_contents($cacheFile, $json, LOCK_EX);

Une empreinte MD5 unique par combinaison de paramètres. Si le fichier existe et a moins de 24 h, on le renvoie sans toucher la base.

2 · Pagination

Ex. : api/club_stats.php:16-24

$recPage   = max(1, (int)($_GET['rp'] ?? 1));
$recLimit  = 10;
$recOffset = ($recPage - 1) * $recLimit;   // → SQL LIMIT $recLimit OFFSET $recOffset

Toujours le même calcul : offset = (page − 1) × limit. Chaque section (records, épreuves…) a sa propre pagination indépendante.

3 · Batch query — éviter le N+1

Ex. : api/similar.php:521-526

// Au lieu d'une requête PAR athlète (le « problème N+1 »), une seule avec IN()
$finIds = implode(',', array_map(fn($c) => (int)$c['id_athlete'], $candidates));
$nivRes = $conn->query("SELECT id_athlete, GROUP_CONCAT(DISTINCT code_niveau) AS niveaux
                       FROM athlete_niveaux WHERE id_athlete IN ($finIds) GROUP BY id_athlete");
while ($nr = $nivRes->fetch_assoc()) $nivMap[(int)$nr['id_athlete']] = $nr['niveaux'];
✅ Pourquoi
Charger les niveaux de 50 athlètes en boucle = 50 requêtes. Avec IN(...) + GROUP_CONCAT = 1 seule requête. Sur 300k athlètes, c'est la différence entre 1 s et un timeout.

4 · Filtre universel $athFilter

Ex. : api/club_stats.php:66-75 — réutilisé dans ~30 requêtes du même fichier

$athFilter = '';
if ($filterNat !== '' || $filterSexe !== '' || $filterCat !== '') {
    $afConds = [];
    if ($filterNat  !== '') $afConds[] = "_af.nationalite_athlete = '".$conn->real_escape_string(strtoupper($filterNat))."'";
    if ($filterSexe !== '') $afConds[] = "_af.sexe_athlete = '".…;
    $athFilter = " AND ac.id_athlete IN (SELECT _af.id_athlete FROM athletes _af WHERE ".implode(' AND ', $afConds).")";

Une seule chaîne construite une fois, injectée dans toutes les requêtes pour appliquer le même filtre (nationalité/sexe/catégorie) sans dupliquer la logique.

5 · Détection temps vs distance

Ex. : api/athlete.php:39-41

function _isDistEp($nom) {
    return (bool)preg_match('/(poids|disque|javelot|marteau|hauteur|perche|longueur|triple|decathlon|heptathlon|pentathlon)/i', $nom);
}

Détermine si une épreuve est un lancer/saut (plus grand = meilleur, tri DESC) ou une course (plus petit = meilleur, tri ASC). Indispensable pour trier les perfs et interpoler le barème dans le bon sens.

7 · Détection de l'IP réelle (CloudFlare / proxy)

Ex. : core/ip_logger.php, core/search_limit.php:42, index.php:24

$ip = $_SERVER['HTTP_CF_CONNECTING_IP']      // CloudFlare en priorité
   ?? $_SERVER['HTTP_X_FORWARDED_FOR']       // puis proxy
   ?? $_SERVER['REMOTE_ADDR'] ?? '';          // enfin direct
$ip = trim(explode(',', $ip)[0]);                // 1er IP si liste séparée par virgules

Derrière CloudFlare, REMOTE_ADDR est l'IP de CloudFlare, pas du visiteur. On lit donc d'abord HTTP_CF_CONNECTING_IP. Ce même ordre est répété partout (quotas, logs, anti-scraping).

8 · Protection des fichiers de logs JSON

Ex. : tous les fichiers logs/.xxx.php

// Écriture : on préfixe TOUJOURS par un die() PHP
@file_put_contents($file, "<?php die('Acces interdit'); ?>\n" . json_encode($data), LOCK_EX);

// Lecture : on saute la 1re ligne avant de décoder
$raw = file_get_contents($file);
$pos = strpos($raw, "\n");
$data = json_decode(substr($raw, $pos + 1), true);
✅ Astuce de sécurité
Le fichier a l'extension .php et commence par <?php die(); ?>. Si quelqu'un l'ouvre par URL, PHP l'exécute, voit le die() et s'arrête → le contenu JSON n'est jamais exposé.

9 · Hiérarchie des niveaux (JS + PHP)

JS : public/assets/js/utils.js · PHP : api/club_stats.php:93, index.php:73

// Le "score" de chaque code (plus haut = meilleur)
$order = ['IE'=>100, 'IR'=>99];
foreach (['N'=>90, 'R'=>80, 'D'=>70] as $p=>$b)
    for ($i=1; $i<=8; $i++) $order[$p.$i] = $b - $i;
// → IE(100) > IR(99) > N1(89)…N4(86) > R1(79)…R6(74) > D1(69)…D8(62)

La couleur du badge dépend de la première lettre : I = fuchsia, N = rose, R = cyan, D = orange. highestNiveau(arr) renvoie le code au score le plus élevé d'une liste.

10 · Barème FFA — performance → points → niveau

Ex. : api/athlete.php:43-93 (répliqué dans nom.php et similar.php)

Le barème (config/bareme_hommes.php) contient, par épreuve, des points de repère [points, performance]. _perfToFfaPts() trouve où se situe la perf et fait une interpolation linéaire entre deux repères (en tenant compte du sens temps/distance). Puis _ffaPtsToLevel() traduit les points en code :

function _ffaPtsToLevel($pts) {
  if ($pts >= 40) return 'IA';  if ($pts >= 35) return 'IB';
  if ($pts >= 30) return 'N1';  if ($pts >= 28) return 'N2';
  // … jusqu'à D5
}
ℹ️ Pourquoi calculer le niveau ?
Certains athlètes élite n'ont pas la qualification formelle en base, mais leur perf le mérite. Ce calcul permet d'afficher le bon niveau (ex. un athlète sans niveau enregistré mais qui court le 100 m en 10''2 sera affiché IB).
