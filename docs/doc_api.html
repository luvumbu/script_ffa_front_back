Référence complète de l'API REST

Chaque endpoint, ses paramètres, sa réponse, son cache et sa protection
Tous les endpoints sont dans api/. Chacun commence par require config.php (en-têtes JSON + CORS + connexion $conn + auth + logIp()). La convention de réponse est { "success": true, … } ou { "success": false, "error": "…" }.

config.php — le socle (jamais appelé directement)

  • Bloque l'accès direct (403 si on ouvre config.php seul).
  • En-têtes CORS : Access-Control-Allow-Origin: *, méthodes GET/POST/PUT/DELETE/OPTIONS. Répond 204 au preflight OPTIONS.
  • En-tête Content-Type: application/json; charset=utf-8.
  • Définit BK_API_KEY = 'bk_s3cr3t_2026_xK9mP'.
  • Inclut core/db.php ($conn), core/auth.php, core/ip_logger.php + logIp().
  • En local, relâche max_execution_time à 300 s (MySQL non optimisé).
  • Fournit jsonResponse($data, $code) : envoie le JSON et ferme la connexion.

athlete.php GET CACHE 24h

Fiche complète d'un athlète (objet unique, pas un tableau). Charge identité, clubs, records, progressions, résultats, médailles, podiums, sélections, niveaux. Calcule à la volée les niveaux FFA manquants à partir du barème.

Paramètres (un seul des trois identifiants requis)

ParamTypeRôle
idintID externe (athle.fr) — le plus courant
id_athleteintID interne BDD
licencestringNuméro de licence
_allintAdmin : force l'affichage même si visible=0
nocacheintBypass cache

Réponse : { success, visible, identite{…}, clubs[], records[], progressions[], resultats[], medailles[], podiums[], selections[], niveaux[] }. Si masqué : visible:false.

search.php GET CACHE 24h QUOTA

Recherche multi-critères. Au moins un filtre requis. Soumise au quota de recherche (section 12). Renvoie 429 si bloquée.

Réponse : { success, total, page, limit, total_pages, athletes[…], niveaux[], search_used, search_limit, remaining, … }. Chaque athlète inclut top_records[5] et son top_niveau.

ℹ️
Les clubs de plus de 5000 athlètes sont exclus, sauf si on filtre explicitement sur un club.

Liste paginée d'athlètes avec tri et filtres (utilisée par la page Athlètes).

⚠️ Perf
Le filtre année utilise WHERE EXISTS (et non HAVING ni IN (UNION)) : sur Hostinger, IN (UNION SELECT) provoque des timeouts (~74 s).

epreuve_stats.php & ville_stats.php GET CACHE 24h

epreuve_stats.php (nom requis, + page/limit/sexe/categorie) : détecte automatiquement temps vs distance pour le tri. Renvoie total_athletes, par_sexe, par_categorie, nationalites, records paginés, médailles, podiums, top_clubs, top_villes, niveaux_resultats, sélections, progressions.

ville_stats.php (nom requis, + page/limit, niv=D3,D2,R1, nat=FRA,MAR, ans=2023,2024) : stats d'une ville avec filtres niveaux/nationalités/années.

stats.php & top_searched.php GET

stats.php : stats globales du site. detail=1 ajoute les tops (clubs/épreuves/athlètes/villes avec niveaux_pct), top=N (10-200), nocache=1. Score athlète = médailles×5 + podiums×3 + sélections×4 + records.

top_searched.php (cache 10 min) : clubs/athlètes les plus consultés. type=clubs|athletes (requis), limit (max 50), days=1|7|30|365. Lit search_tracking (COUNT(DISTINCT ip) = vues). ?reset=athletes|clubs|all&bk_key=… réinitialise.

clubs.php · epreuves.php · villes.php GET CACHE 24h

Listes paginées des référentiels. Paramètres communs : nom= (recherche), has_athletes=1, page, limit. clubs.php a max_athletes=5000. clubs.php et villes.php appliquent le quota de recherche quand nom= est présent.

similar.php GET CACHE 24h

Profils similaires. id (externe, requis), mode=niveau|perf|epreuve|niveau_sup|niveau_inf, ep=ID (mode épreuve). Regroupe par club (5 athlètes max/club), même sexe. Utilise le barème FFA.

follow.php GET POST

POST = toggle suivre/ne plus suivre. GET = vérifier le statut.

// POST body
{ "athlete_id": 548525, "email": "x@y.com" }   // ou "club_id"
// Réponse
{ "success": true, "following": true, "count": 42 }

Si l'utilisateur est connecté (cookie bk_token), l'email est auto-détecté. Tables athlete_follows / club_follows (avec l'ID externe).

contact.php GET (admin) POST (user)

ℹ️
N'inclut PAS config.php → reste accessible même si l'IP est bloquée.

POST (nom, email obligatoire, message) : envoie un email de confirmation. Le message n'est enregistré (contact_messages) qu'après clic sur le lien (auth/confirm_contact.php). Rate limit : 3/jour/IP.

GET admin (cookie bk_sa_token) : ?mark_read=ID, ?mark_unread=ID, ?delete=ID, ?delete_token=ID, ?unban_ip=X. POST admin : action=reply (répondre), action=send_to_user (mail à un inscrit).

report.php GET (admin) POST (signalement)

POST = signaler un profil (5 motifs : retrait, donnees_incorrectes, usurpation, vie_privee, autre). Si motif = retrait + email → envoie un lien de masquage self-service (auth/confirm_hide.php → visible=0). GET admin : ?hide_athlete=ID, ?show_athlete=ID, ?mark_read=ID, ?resolve=ID, ?delete=ID. Toute action sur la visibilité vide le cache de l'athlète.

search_track.php POST

Endpoint léger qui reçoit le tracking JS (via sendBeacon). Body JSON : { q, type, source, entity_id, entity_name, results, pg }. Insère dans search_tracking. Nettoyage probabiliste : 1 % de chance de supprimer les enregistrements de plus de 90 jours. Renvoie {ok:true}.

quota.php GET

Statut du quota de recherche en lecture seule (ne consomme rien). Appelle bkSearchLimit($conn, false) + bkSlFields(). Sert à rafraîchir le badge de quota dans la nav. Renvoie : search_used, search_limit, cooldown_remaining, anon_trial, trial_remaining, logged, is_sa, unlimited.

✅ Sécurité auth
Les endpoints d'authentification utilisent des requêtes préparées (prepare() + bind_param()) — protection contre l'injection SQL. Les endpoints de lecture (recherche, stats) utilisent souvent real_escape_string() sur des entrées déjà validées/échappées.
